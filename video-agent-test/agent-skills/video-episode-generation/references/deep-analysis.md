# 项目深度复盘：问题剖析 · Skill 修改动因 · 模型边界

本文件是整个项目的核心知识产物。
不记录"做了什么"，只记录"为什么这样做、背后是什么在起作用"。

---

## 一、Seedance 的本质：视觉稳定性优化器，不是叙事导演

理解这一条，才能理解所有问题的共同根源。

Seedance 在生成时的底层目标是：**找到视觉上最稳定、最可复现的输出**。
当"叙事需要的画面"和"视觉稳定的画面"发生冲突时，它总是选择稳定性。

这解释了几乎所有的失败模式：

| 叙事需要 | Seedance 实际做 | 原因 |
|---|---|---|
| Sylvia 目击出轨，表情崩溃 | 中性脸，手放肚子 | 中性脸生成稳定性远高于强情绪表情 |
| 三人在墓地对峙，空间紧张 | 三人平排站，距离均等 | 均等排布是最稳定的多人构图 |
| Sylvia 躲在墓碑后偷看 | Sylvia 直接站在 James 旁边 | 近距离构图比"前景遮挡+背景主体"更稳定 |
| 门被推开，人物在门后 | 门与人物发生穿模 | 物理碰撞计算会引入不确定性，稳定解是忽略遮挡 |
| shot_8 和 shot_9 不同情绪 | 两帧构图几乎相同 | 已找到稳定构图解，不再响应细微差异 |

**这不是 bug，是模型的训练目标决定的。**
接受这个事实是所有 skill 进化的前提。

---

## 二、三个控制层及其真实可靠性

整个项目的 skill 修改历史，本质上是对这三层认知的逐步校正：

```
层级          控制对象                      实际可靠性    原始 skill 的错误假设
─────────────────────────────────────────────────────────────────────────────
视觉层        服装/场景/空间/色调             ~90%        正确认知（靠参考图）
结构层        景别/运镜/站位/人物出入场       ~65%        过于乐观（以为 prompt 文字能精确控制）
表达层        面部表情/情绪弧/微动作/语气     ~25%        严重高估（大量 skill 内容在这一层）
```

**表达层的问题被严重高估**：原始 skill 文件里有大量描述如何写表情、如何渲染情绪——但这整个层级对 Seedance 的实际影响非常有限。射程不足的子弹射出去也是白费。

**结构层的问题被低估**：站位、镜头轴线、人物出入场方向——这些是 65% 稳定性的中档，是真正值得花精力控制的层。

## 三、问题深度剖析

### 【问题组 A】情绪与表达

#### A-1 情绪误读：引信被当爆破处理
**表象**：shot_1b v3-v5.1 全部生成了"Sylvia 含泪崩溃"。
**直接原因**：没读剧本全文，用对话片段孤立判断情绪。
**深层原因**：情绪在叙事中是相对的，不是绝对的。
"Don't wait up." 作为孤立句子，语义指向离别/永别。
但在完整剧情上下文里，它是引信——真正的爆破在三分钟后的墓地。
**本质**：情绪定位是叙事位置问题，不是台词语义问题。
任何基于"本镜对白意思"推导情绪的方法都是错的；必须基于"本镜在整集叙事弧里的位置"。

**Skill 修改**：WORKFLOW.md 增加 P0 规则（必须先 Read 完整剧本）+ Step 2 的三行强制 frontmatter（`shot_function` / `prev_shot_recap` / `next_shot_setup`）。三行不是表单，是强制的叙事位置坐标系——写不出来就说明位置还没定位清楚。

---

#### A-2 表情压平：Seedance 只有一张脸
**表象**：所有版本的 Sylvia，无论是厨房切菜、墓地目击出轨、还是听到背叛，表情几乎相同——微微下垂的眼睛，略张的嘴。
**深层原因**：见第一节。中性脸是稳定解，强情绪表情是高方差解。
**关键认知**：我们一直在纠正"情绪写错了"——但看帧之后发现，
所谓"正确情绪的 v6"和"错误情绪的 v3"，表情差异在视觉上几乎无法区分。
**Seedance 根本就没有在任何版本里渲染出可读的表情差异。**
"修正情绪方向"影响的是叙事逻辑，不是 Seedance 会不会真的渲染出不同表情。

**隐含结论**：互动剧的情绪必须靠**身体语言 + 站位关系 + 镜头角度**来传达，不能靠表情。表情是点缀，不是载体。

**Skill 修改**：DIRECTOR_PLAYBOOK.md 明确"景别变化是控情绪曲线最稳的工具"——这不是审美建议，是承认表情不可靠后的替代方案。SEEDANCE_LESSONS.md 的三档能力表，以及"弱档表情必须配强档身体动作"铁律，都是对这一认知的工程化。

---

#### A-3 弱档动作堆叠与注意力稀释
**表象**：含泪 + 颤抖 + 嘴唇颤——三个全都没落地。
**深层原因**：Seedance 的 text encoder 是单一注意力分配，不是并行处理多指令。
每增加一个动作描述，其他描述分到的注意力就减少一份。
三个弱档（每个单独稳定性 ~30%）叠加后，每个只有 ~10% 权重，全部低于感知阈值。
**关键认知**：写更多不等于要求更多。在注意力总额固定的系统里，
"写三件事"等于"每件事只要求三分之一"。

**Skill 修改**：SEEDANCE_LESSONS.md Lesson #1（能力三档）+ Lesson #7（prompt 预算分配）。不只是"弱档要少写"，而是整个 prompt 的注意力分配都是零和游戏——辅助内容每多一段，表演段就少一分。

---

### 【问题组 B】空间与连续性

#### B-1 跨镜头空间记忆为零
**表象**：Sylvia 从墓碑后偷看，下一镜直接站在 James 旁边；女主倒下的位置和男主抱起她的位置不一致。
**深层原因**：Seedance 没有跨 shot 的空间状态记忆。
每个 shot 生成时，它只有：当前 prompt 文字 + 当前参考图。
末帧 PNG 是一个"假记忆"——它告诉模型"上一帧的姿态是什么"，
但它不告诉模型"这个人在整个场景空间里的位置关系是什么"。
**关键认知**：末帧 PNG 解决的是**时间连续性**（姿态承接），
解决不了**空间连续性**（人物在场景中的全局站位）。
这是两个独立问题，之前混为一谈。

**Skill 修改**：WORKFLOW.md Step 3 新增 `shot_X_spatial.png`（空间参考帧）机制——与末帧 PNG 分工：末帧负责时间，空间参考帧负责全局站位。Step 7 新增强制提取空间参考帧的流程。SEEDANCE_LESSONS.md 新增 Lesson #12（末帧 ≠ 空间参考，复杂场景必须双帧分工）。

---

#### B-2 人物在场景末段消失（空 end frame）
**表象**：shot_2b_end 和 shot_4_end 是空厨房，一个人都没有。
**深层原因**：模型在长镜头末段优先收敛到最稳定的构图。
对于厨房场景，"只有蔬菜和橱柜的整洁场景"比"有人物的场景"生成更稳定。
当 prompt 里的人物动作描述结束后，模型开始"放松"，背景场景占主导。
**关键认知**：三重静止收尾规则（人物静止 + 镜头静止 + 构图锁定）
不只是审美要求——是防止模型在末段"自行清场"的技术约束。
人物必须在末帧保持明确存在感，否则下一镜的时间承接锚点丢失。

**Skill 修改**：DIRECTOR_PLAYBOOK.md 的第 5 条（三重静止收尾）明确标注为"技术约束，不是审美选择"。
SEEDANCE_LESSONS.md Lesson #8（ARK SOP）里的"第一动词必须是渐变动词"也与此相关——末帧如果是空场景，首帧承接就直接断。

---

#### B-3 关键情绪时刻脸被藏掉
**表象**：shot_6a_end，Sylvia 目击出轨的第一反应镜头，镜头给了她的后脑勺。
**深层原因**：背影构图比正面 / 侧面构图生成稳定性更高——不需要渲染表情。
当 prompt 没有明确约束"人物面部必须可见"时，
模型在追求稳定构图的过程中会选择背影。
**关键认知**：情绪顶点 = 最需要看到人物表情的时刻 = 模型最容易逃避渲染表情的时刻。
这两者天然对立——情绪越强烈，模型越倾向于背影或侧脸。
必须在 prompt 里显式约束"正面 / 四分之三正面 / 面部可见"。

**Skill 修改**：WORKFLOW.md Step 5.5（Prompt Review）Group 4 加入"独白/内心戏禁止大特写"铁律，同时在 Group 2（空间连续性）中加入"L3/L4 场景 review agent 必须打开 spatial.png 看图核查朝向"。

---

### 【问题组 C】Prompt 工程

#### C-1 无固定结构 → 输出不可预测（最重要的工程问题）
**表象**：手写 prompt 每次结构不同，输出质量随机波动大。
**深层原因**：Seedance 的 text encoder 对信息顺序敏感。
早出现的信息获得更高的基础权重（类似 context window 的注意力分布）。
手写 prompt 的信息顺序每次不同 → 每次注意力分配不同 → 输出变化难以预测。
**关键认知**：结构化时间戳格式（【镜头1 · 0-2s · 景别 · 运镜】）
不只是让 prompt 更"整洁"——它是给模型一个**可预测的注意力分配框架**。
分段后每段的权重相对稳定，跨版本迭代时只需修改具体描述，骨架不变。

**对比测试验证**（对比test.xlsx）：结构化格式在镜头切换和调度上明显优于手写版，但在人物刻画上有时弱于手写（因为手写的"情感密度"更高，所有注意力集中在表演段）。

**结论**：结构化格式是量产和可控性的保证；手写格式的情感密度更高但稳定性差。
最优解是：**结构化骨架（时间戳分镜）+ 高密度表演段文字（手写风格的情感描述）**。

---

#### C-2 画外音空间感无法渲染
**表象**：ep3，走廊里两人说话，厨房里的 Sylvia 偷听。模型无法区分"走廊传来的声音"和"同室对话"。
**深层原因**：Seedance 的 audio 和 video 是同一模型同时生成的，
不是先生成画面再配音。"声音从特定空间方向传来"这个概念对它来说是视觉+听觉的联合约束，
而它的空间理解能力有限（见 B-1）——既然它不能可靠地维持空间关系，自然也无法渲染"声音从门缝传来"这类依赖空间感的音效。
**目前无完美解法**：可以在 prompt 里强调"画外音（走廊）voiceover"并在场景描述里说明"门虚掩，门缝透光"，但效果不稳定。

---

#### C-3 TTS 不响应语气形容词，只响应句式结构
**表象**：ep1 结构化版本，James 台词"说的非常匆忙"，语气节奏不对。
**深层原因**：TTS 模型的训练数据是语音-文字对——它学到的是"这种断句/标点/句子长度通常是什么语气"，
没有学"这个语气形容词意味着什么发音方式"。
"他冷静地说"在 TTS 看来和"他说"没有区别——"冷静地"是语义描述，不是音频特征。
但"I know. I've always known."（短句+句号停顿）在训练数据里有大量对应的克制语气音频。
**关键认知**：TTS 的情绪控制是**句法工程**，不是**语义描述**。
把情绪编码进标点、句子长度、断句方式，而不是用形容词描述。

---

### 【问题组 D】角色一致性

#### D-1 服装幻觉：模型自行添加或修改服装
**表象**：ep1 结构化版本，Sylvia 莫名多了围裙；ep2，Kennedy 服装被修改。
**深层原因**：模型的服装生成有两个来源：参考图（立绘）和训练数据里的"合理服装"推断。
当 prompt 描述了某个场景（厨房+切菜），训练数据里大量"厨房切菜"场景包含围裙，
模型的先验知识会倾向于生成围裙——即使参考图里没有。
**关键认知**：参考图的服装约束能力在 ~90%，但不是 100%。
场景语境会激活训练数据里的服装先验——厨房→围裙，护士→白大褂，厨师→厨师帽。
需要在 prompt 里明确写"禁止添加围裙/帽子/任何参考图外的服装配件"。

### SEEDANCE_LESSONS.md（从零建立）

**建立动因**：原始知识散落在 WORKFLOW.md、CHARACTER_DNA.md、DIRECTOR_PLAYBOOK.md 三个文件，
各文件混杂着"流程规则"和"模型经验"，导致两类知识互相稀释。
建立独立文件的目的：把**实测摔出来的 Seedance 专属经验**从流程规则里剥离出来，单独沉淀。

| Lesson | 核心洞察 | 建立触发 |
|---|---|---|
| #1 能力三档 | 动作控制能力由物理半径决定，≥20cm 强档 / 5-20cm 中档 / ≤5cm 弱档 | 弱档动作堆叠导致全部失效 |
| #2 反向校准×2 | Seedance 情绪渲染衰减约 50%，需将目标强度×2 写进 prompt | shot_1b_v3 含泪几乎不可见 |
| #3 道具激活时间点 | 服装是永恒层；道具触碰是剧情触发层——混淆导致剧情穿帮 | 银手链在激活前被多次写入 |
| #4 情绪定位铁律 | 本镜情绪取决于下一镜走向，不取决于本镜对白本身 | shot_1b v3-v5.1 引信当爆破 |
| #5 三层 reference 架构 | 空间地图+时间承接+角色 DNA 各负其责；reference 稳定性 >> prompt 文字 | 跨镜一致性失控问题 |
| #6 reference 过载稀释 | 超过 4 张参考图后，文本表演段注意力被稀释 | shot_1b_v5 情绪退化 |
| #7 prompt 预算分配 | 表演段占比 ≥ 50%，辅助内容 ≤ 50%；整个 prompt 是注意力零和游戏 | shot_1b_v5 辅助文字挤占 |
| #8 ARK 真人检测 | 任何视频输入被拦截，图片不受影响 | 视频输入发现被拒 |
| #9 TTS 敏感词 | mine/shot/kill 等词触发音频审核失败 | shot_1b 台词被拦截 |
| #10 TTS 句法工程 | TTS 响应断句/停顿/句子长度，不响应语气形容词 | ep1 台词节奏失控 |
| #11 表情档位边界 | 全镜弱档表情 ≤2 个；弱档必须配强档身体动作；不能单独依赖表情传情绪 | 帧分析后确认表情压平是系统性问题 |
| #12 末帧 ≠ 空间参考 | 末帧只锁时间承接；空间参考需从视频中独立选取全景帧 | 发现时间和空间连续性是两个独立问题 |

### CHARACTER_DNA.md

**原始问题**：文件把所有"角色相关属性"混在一起，没有区分"永恒不变"和"条件触发"两类，
导致把剧情触发的动作当永恒 DNA 写进去。

| 修改内容 | 动因 |
|---|---|
| 删除色温/光温/焦段/灯型锁定项 | 这些是 Seedance 弱档，文字描述基本不响应，靠参考图锁更有效；列在 DNA 里只是误导 |
| 删除招牌动作（如左手摸手链） | 招牌动作是剧情触发层，不是永恒层；在激活点前写进 prompt 会导致剧情穿帮 |

| 服装来源改为指向 ep_X.json | 在 CHARACTER_DNA 里维护服装副本会与剧本失同步；权威源应只有一个 |
| 保留：服装 / 发型 / 身材 / 孕肚 / 立绘文件映射 | 这些才是真正意义上跨集不变的角色物理属性 |

### SKILL_REVIEWER.md（从零建立）

**建立动因**：随着项目推进，skill 文件多次被修改，
缺乏一个机制验证"修改后的文件是否达到质量标准"——
没有检测机制，skill 文件会因为遗忘或局部更新而悄悄退化。

Reviewer 的设计原则：
- 每条检测项都对应一个真实翻车过的问题
- 检测标准可操作（yes/no，不是主观判断）
- 触发时机明确（新 episode / 修改 skill 文件 / 翻车复盘）

## 五、总结：认知演进时间线

```
初始状态
│ 假设：模型是叙事导演，能理解情绪和空间逻辑
│ skill 文件：充满真人电影词汇，大量弱档技巧，服装/灯光锁定
│
├─ 发现 ARK 技术拦截（视频输入/TTS敏感词）
│  → 删除视频输入相关流程，建立末帧 PNG 替代方案
│
├─ 发现情绪误读系统性问题（shot_1b v3-v5.1）
│  → 建立"先读完整剧本"P0 规则，三行叙事坐标强制输出
│  → 认知更新：情绪是叙事位置，不是台词语义
│
├─ 发现能力三档和反向校准（弱档堆叠全部失效）
│  → 建立 SEEDANCE_LESSONS.md
│  → 认知更新：不同半径的动作，模型控制能力差异巨大
│
├─ 发现参考图架构（reference 稳定性 >> prompt 文字）
│  → 建立三层 reference 标准架构
│  → 认知更新：视觉层应靠图锁，而不是文字描述
│
├─ 发现 prompt 预算零和问题（v5 辅助内容挤占表演段）
│  → 建立 50%/50% 分配规则
│  → 认知更新：加一段约束 = 减一分表演质量
│
├─ 实际看帧后发现更深问题（帧分析）
│  → 认知更新：表情压平是系统性问题，不是个别版本问题
│  → 认知更新：空间连续性和时间连续性是两个独立问题
│  → 建立 spatial.png 双帧分工机制
│
├─ 对比测试 Excel 补全最后几块拼图
│  → 结构化时间戳格式的工程价值得到验证
│  → TTS 句法工程确认，服装幻觉、穿模、画外音空间感记录
│
└─ 当前认知
   核心结论：Seedance 是视觉稳定性优化器
   可靠控制的：视觉层（参考图）+ 结构层（时间戳分镜骨架）
   不可靠的：表达层（情绪/微表情/语气）
   工程方向：用身体语言和镜头结构替代无法可靠渲染的表情弧
```
