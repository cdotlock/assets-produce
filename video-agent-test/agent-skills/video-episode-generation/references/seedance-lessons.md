# Seedance 实测经验沉淀

本文件是本项目 v1→v6 摔出来的 **Seedance 2.0 专属 know-how**，不是通用知识。
每条都标注**来源镜头 + 翻车案例**作为佐证——下次想违反时回头看这条。

---

## 1. Seedance 能力三档（最重要）

按动作发生的物理半径，Seedance 可控性差异巨大：

| 档位 | 半径 | 例子 | 稳定性 | 写法 |
|---|---|---|---|---|
| **强档** | ≥ 20cm | 推门、转身、走两步、举手、握刀、覆腹、攥门框、抱住、跪下 | ~95% | 直接白描 |
| **中档** | 5-20cm | 头部转向、嘴型张合、肩膀起伏、手指攥褶皱、解围裙带、目光从 A 移到 B | ~70% | 反向校准 1.5× + 锚图固化起手姿态 |
| **弱档** | ≤ 5cm | 含泪悬挂、嘴角下撇、喉结滚动、瞳孔微缩、伦勃朗光、3200K 色温、TTS 哭腔语气 | ~30% | **首尾帧双锚硬绑** + 反向校准 2× + 写到"过分激烈"程度。或放弃，靠场景图/立绘锁 |

**实操规则**：
- 写 prompt 前先标每个动作档位
- **一镜里弱档动作 ≤ 2 个**（再多模型注意力扛不住）
- 弱档动作必须锚图加持，不能只靠 prompt 文字
- **翻车案例**：`shot_1b_v3–v5.1` 翻车的核心原因——把"含泪 + 颤抖 + 嘴唇颤"三个弱档堆在一起，每个都没落地；`shot_1b_v6` 改为单次解围裙带（强档）才稳定

## 2. Seedance 衰减反向校准（×1.5-2）

**Seedance 对情绪强度的渲染会衰减约 50%**——你写"颤抖"，模型出"轻微抖动"；你写"剧烈颤抖"，模型出"颤抖"。

**反向校准公式**：
```
最终想要的画面强度  =  prompt 写的强度 × 0.5
所以：prompt 写的强度  =  目标强度 ÷ 0.5  =  目标 × 2
```

实操：
- 想要"明显含泪" → 写"眼眶湿润度达到 100% 一颗泪悬在睫毛上欲落不落"
- 想要"嘴唇微颤" → 写"嘴唇可见颤抖"
- 想要"目光警觉" → 写"目光收成一道细线钉死目标"

**反例**：`shot_1b_v3` 写"Sylvia 含泪"——出片几乎看不出。`shot_1b_v4` 改写"眼眶湿润度达到 100% 一颗泪悬而欲落"——刚好看到。

**注意**：这个校准只适用于**情绪/微表情**层。强档大动作（推门/转身）不需要校准——写"推门" Seedance 就推门，写"猛推门"反而可能崩成戏剧化夸张。

## 3. 道具/钩子的"激活时间点"铁律

**剧本里的所有 symbol 不是"角色固定 tell"，是"剧情触发后的反射"**。

每个道具/动作 tell 必须显式标注激活时机：

```yaml
symbol: 银手链
owner: Sylvia（左手腕，James 三年前求婚时所赠）
trauma_activation_after: shot_5（墓地目击 James 与 Kennedy 拥抱之后）
forbidden_before_activation: 严禁用作"摸手链/触碰手链/手指蹭金属"等创伤反射动作
```

**翻车案例**：
- shot_1b v3-v5.1 + shot_2b v1：把"左手摸银手链"当成 Sylvia 的角色 DNA 写进 prompt——但此时（shot_1b）**Sylvia 还没目击出轨，创伤钩没激活**，写了等于剧情穿帮（观众看到她无端摸手链会困惑）
- 修正：shot_1b_v6 完全删除手链触碰动作；激活时间挪到 shot_5+ 的墓地戏后

**推广**：
- 服装/发型/身材是**永恒**层（始终一致）
- 道具触摸/特定身体动作是**剧情触发**层（按激活时间表用）
- 禁忌动作也是**剧情触发**层（同一动作在 EP1 禁、EP10 解禁）

## 4. 情绪定位铁律：本镜情绪取决于下一镜

**最反直觉但最重要的一条**——参考 WORKFLOW 失败模式 #7。

**孤立的对白没有情绪强度**。"Don't wait up." 单看像永别（→ 推情绪到崩溃），知道下一场是墓地目击出轨（→ 妻子起疑+决心要跟）。

**强制 SOP**：
- 写 shot prompt 第一件事：Read `script/ep_X.json` 全文
- 在 frontmatter 写出三行 `shot_function` / `prev_shot_recap` / `next_shot_setup`
- 任一行写不出 → 回去读剧本，不准动笔

**翻车案例**：shot_1b v3→v4→v5→v5.1 全部错——把引信镜头当爆破镜头处理。v6 修正后即对。同问题再现于 shot_2b / shot_3 / shot_4（厨房戏全段）——见剧本扫描报告。

## 5. 三层 reference 架构

跨 shot 一致性的真正抓手不是 prompt 文字，是**三层参考图分工**：

| 参考层 | 来源 | 解决 |
|---|---|---|
| 空间地图 | `{作品}/assets/scene_*_panorama.png`（21:9 三墙全景） | 房间结构、门窗位置、材质色板、光温 |
| 时间承接 | `{作品}/episodes/ep_{N}/end-frames/{prev_shot_id}_end.png`（前一 shot 末帧 PNG） | 站位、姿态、衔接前一镜 |
| 角色 DNA | 立绘（按 CHARACTER_DNA.md 映射） | 服装、发型、身材、孕肚、配饰 |

**`assets.images` 顺序**：场景地图 → 末帧承接 → 角色立绘。

prompt 里必须显式写"参考图分工硬约束"段落，告诉模型每张图各自负责什么——`shot_1b_v5` 验证：场景图必须明确"仅取空间结构，忽略其 21:9 横屏画幅与 45° 高角度"，否则会被带偏画幅。

角色立绘的写法只保留 **@图N 主参考约束**：写"外貌/服装/身材/孕肚/配饰全部以 @图N 为准"，不要把图中具体衣着和外貌逐项枚举。逐项枚举会占用 prompt 预算、稀释表演层，并可能和参考图形成二次解释冲突。

**实测**：reference 稳定性 >> prompt 文字。"伦勃朗光 3200K" 不响应，但参考图直接给一张立刻锁住。

## 6. Reference 数量过载稀释

多参考图会**稀释文本 prompt 的注意力权重**。每多一张图，文本对"表演层"的注意力被分走一份。

**建议上限**：4 张参考图（含场景地图 + 末帧承接 + 1-2 张角色立绘）。

5 张以上 → 情绪/台词渲染明显退化。

**翻车案例**：`shot_1b_v5` reference 4 张（已是上限），但同时换 fast 模型 + 加大段空间约束文字 → 三因素叠加，情绪退化到 `shot_1b_v3` 之前水平。教训：**架构验证不能同时改多个变量**。

## 7. Prompt 预算分配

Seedance 的 text encoder 注意力总额有限——加一段就稀释一段。

**实操规则**：
- **核心表演段（情绪+台词+身体动作）必须占 prompt 总长度 ≥ 50%**
- 空间约束 / reference 分工 / 禁忌清单合计 ≤ 50%
- 超出 → 砍禁忌清单（保留最关键 3-5 条），不能砍表演段

**翻车案例**：`shot_1b_v5` 加入大段空间约束文字（"门窗位置/45°高角度忽略"等），导致表演段比例跌破 50%，情绪渲染退化到 `shot_1b_v3` 水平。修正为 `shot_1b_v5.1` 删除冗余约束后恢复。

## 8. 连续镜头动态承接：上一镜 15 秒尾段

只靠末帧图片可以锁姿态，但会丢掉上一镜的动作惯性和镜头运动。分发版统一通过内部网关处理连续镜头。

**强制 SOP**：
- 生成视频只通过 `scripts/bin/videoctl submit <prompt.md> --wait` 或 `scripts/bin/videoctl run-shot <prompt.md> ...`；网关端点由 videoctl 内部调用，Agent 不手写 HTTP 请求
- 调用前所有图片/视频素材都必须先上传 OSS；payload 中不允许出现本地路径或 base64
- `scripts/bin/videoctl payload` 只用于预览/排查 payload，不用于手动 POST；它会拒绝没有 OSS URL 或 `.url` sidecar 的本地素材
- `shot_2+` 必须把上一镜视频 URL 放入 `sourceVideoUrls`
- 多参考图：`sourceImageUrl` 传主参考图（空间/首帧），`referenceImageUrls` 传其余（场景图、角色图、末帧锚图）
- 时间承接仍保留**前一 shot 末帧 PNG/JPG**，用于 prompt 参考和画廊复盘
- 关键场景 ① 第一动词必须是渐变动词（缓/微/渐/轻/慢）承接首帧姿势

详细规避清单见 WORKFLOW 失败模式 #5。

## 9. TTS 英文敏感词清单

音频生成有概率触发安全过滤——**对白里有以下词汇时主动改写**，避免浪费一次生成成本：

| 危险词 | 同音/误识 | 替换示例 |
|---|---|---|
| `mine` | landmine（地雷） | `my call` / `my own` |
| `shot` | 射击 | `take` / `attempt` |
| `gun` | 武器 | 上下文重写 |
| `kill` | 杀 | `end` / `take down` |
| `drug` / `pill` | 毒品 | 上下文重写 |
| `dead` / `blood` | 暴力 | `passed` / `gone` |
| 角色名碰巧是英文实词 | Hunter/Storm | 保留但提高警惕 |

**翻车案例**：shot_1b 早期版 "Stay. This one's mine." → 触发 mine 检测。改 "Stay. This is my call." 即过。

## 10. 情绪→台词语气 TTS 写法

> 新增原则，尚无实测翻车案例——待验证后补入 shot_id + 版本号佐证。

**核心规律：TTS 响应句式结构，不响应语气形容词。**

"她悲伤地说"对 TTS 没有作用；把悲伤编码进断句、停顿、句子长度，TTS 才会有对应输出。

| 情绪状态 | ❌ 无效写法 | ✅ 有效写法（句式结构） |
|---|---|---|
| 压抑 / 克制 | "平静但内心痛苦地说" | 短句 + 停顿："I know. I've always known." |
| 崩溃 / 激动 | "颤抖着哭泣地说" | 断句 + 词语重复："It's not— it's not what I thought. None of it." |
| 冷静 / 权威 | "冷漠地命令" | 长句无断点，陈述句结尾："You will stay. That is final." |
| 犹豫 / 内疚 | "犹豫不决地开口" | 自我打断 + 省略："I wanted to tell you— I just... couldn't." |
| 讽刺 / 轻蔑 | "讽刺地笑着说" | 倒装 / 反问："And you think that matters? Now?" |
| 强装镇定（实则崩边缘） | "勉强撑着说" | 前半句正常节奏，后半句骤然截断："Everything is fine. Everything is—" |

**停顿工具**：
- `...` = 情绪悬挂、说不下去、内心波动
- `——` = 被打断、自我截断、情绪骤变
- 句子越短 = 情绪越收紧；句子越长越无停顿 = 控制感越强

**反向校准（TTS 版）**：TTS 对情绪强度同样衰减——想要"明显停顿感"，省略号要连用（`I know... I know...`）；想要"断裂感"，破折号后直接不接完整词（`She's gone——`）。单个标点衰减后几乎无感。

## 11. 表情丰富度的写法边界

> 新增原则，尚无实测翻车案例——待验证后补入 shot_id + 版本号佐证。

动漫赛璐璐风格对表情的容忍度比写实高，但 Seedance 的表情控制仍然按档位差异极大。

| 表情类型 | 档位 | 稳定性 | 推荐写法 |
|---|---|---|---|
| 眼神方向 / 焦点 | 中档 | ~70% | "目光锁定 X 方向" / "视线从 A 缓缓移到 B" |
| 眼眶湿润 / 泪水 | 弱档 | ~40% | 反向校准 ×2："眼眶湿润度 100%，一颗泪悬在睫毛上欲落不落" |
| 嘴唇动作（颤 / 抿） | 弱档 | ~30% | 首尾帧双锚才能稳定；单靠文字几乎不响应 |
| 微表情（嘴角 / 眉头） | 弱档 | <25% | 基本不可控；用身体动作代替表意 |

**铁律：弱档表情必须配强档身体动作，才能有感染力。**

表情单独写没有重量；强档动作承载情绪主体，弱档表情作为点缀：

| ❌ 只写表情 | ✅ 强档动作 + 弱档表情配对 |
|---|---|
| "嘴唇轻颤，眼眶泛红" | "手指攥紧裙角（强档），嘴唇微颤（弱档）" |
| "眉头皱起，眼神涣散" | "身体向后退半步（强档），目光虚焦投向窗外（中档）" |
| "嘴角苦涩地弯了一下" | "缓缓放下手中的杯子（强档），嘴角牵动一下随即压回（弱档）" |

**表情丰富度不靠"写多个表情"实现**——全镜弱档总数 ≤2，超出后模型注意力分散，每个都落不了地。选最关键的 1 个弱档表情，其余情绪靠强档动作承载。

## 12. 末帧 ≠ 空间参考——复杂场景必须双帧分工

> 新增原则，尚无实测翻车案例——待验证后补入 shot_id + 版本号佐证。

**问题**：末帧（最后 0.1-1 秒）常常是情绪特写或人物局部，无法反映场景的空间关系——用它做下一镜的空间参考，agent 无法确认站位和说话方位，Seedance 也无法捕捉全局位置，导致穿帮。

**双帧分工**（L3/L4 场景强制执行，L1/L2 若末帧为特写也需补提取）：

| 帧类型 | 文件名 | 解决什么 | 来源 |
|---|---|---|---|
| 时间承接帧 | `{作品}/episodes/ep_{N}/end-frames/shot_X_end.png` | 交接瞬间的姿态 / 表情 | 自动抽取最后帧 |
| 空间参考帧 | `{作品}/episodes/ep_{N}/end-frames/shot_X_spatial.png` | 场景布局、人物站位、说话朝向 | Agent 自动筛选（见 SKILL.md Step 7） |

**空间参考帧筛选流程**（由 agent 执行，无需人工）：
1. ffmpeg 每 2 秒抽一张候选帧（`shot_X_cand_01.png` 等）
2. Agent 逐一读取候选帧图片，按优先级选最优：所有人物可见 → 景别最宽 → 站位方向清晰
3. 最优帧存为 `shot_X_spatial.png`，候选帧临时文件删除
4. 若所有候选帧均为特写或人物不全，退回使用 panorama 并告知用户

**在 `assets.images` 中的位置**：L3/L4 续镜中，空间参考帧**替代**场景全景图（panorama）——它包含真实人物分布，比静态 AI 生成的全景图更准确，且维持总图片数 ≤4：

```yaml
# L3/L4 续镜（同一场景）
assets:
  images:
    - https://.../shot_X_spatial.png      # 空间层（替代 panorama）
    - https://.../shot_X_end.png          # 时间层（姿态承接）
    - https://.../[角色立绘].png           # 角色 DNA
  videos:
    - https://.../shot_X.mp4              # 动态承接来源，实际请求传 sourceVideoUrls
previous_video_url: https://.../shot_X.mp4
previous_frame_url: https://.../shot_X_end.jpg
```

**写 prompt 前的强制动作**：agent 必须打开 `shot_X_spatial.png` 看图，从中读出每个角色站在画面哪侧、面朝哪个方向、彼此距离，再写下一镜的站位描述——不得凭记忆或剧本文字推测。

## 13. 群像人物差异化（背景角色克隆问题）

**问题来源**：`shot_ep11_2b` 系列——议事厅所有长老都生成同一张脸（白发长老克隆体）。

### 根本原因

Seedance 的 background character 逻辑：没有立绘参考时，模型对同类型角色（"老年男性深色西装"）默认复用同一套脸部模板，描述越模糊克隆越严重。

### 有效的差异化方法（按效果排序）

| 方法 | 效果 | 说明 |
|---|---|---|
| **立绘文件（@图N）** | ★★★★★ | 最可靠。每个关键人物一张立绘，效果100%锁定 |
| **轮廓型差异** | ★★★★ | 秃头 vs 长发、极瘦 vs 宽壮、眼镜 vs 无眼镜，模型响应好 |
| **服装类型差异** | ★★★★ | 战术装 vs 西装、大衣 vs 夹克，比颜色差异更有效 |
| **性别差异** | ★★★★ | 在同质化人群中放一位女性，一定会被区分出来 |
| **年龄段跨度** | ★★★ | 30岁 vs 70岁差异明显；55岁 vs 65岁基本无效 |
| **面部特征** | ★★★ | 络腮胡 vs 山羊胡 vs 干净剃须，有差异但不稳定 |
| **颜色差异（仅发色）** | ★★ | 白发 vs 灰发几乎无效；白发 vs 黑发有效 |
| **文字个人描述** | ★ | 仅文字不配立绘，5人以上基本无效 |

### 实战公式（无立绘时）

```
① 确定 2 个"锚点人物"：立绘存在 → 直接引用；无立绘 → 服装/性别完全不同
② 其余人用"轮廓型"特征区分：
   - 一人完全秃头
   - 一人戴厚框眼镜
   - 一人极度消瘦（颧骨突出）
   - 一人体型宽胖
   - 有东亚面孔需求时：明确写"东亚面孔"
③ 严禁写"有人白发、有人灰发"——这不是差异，这是克隆
④ 人物总数 ≤ 8 人：人越少，模型分配给每个人的细节越多；10人以上几乎必定克隆
⑤ 把两个锚点人物放在"左侧第一位"和"右侧第一位"——最靠近镜头，最清晰可见
```

### 实测结果（`shot_ep11_2b` 系列）

- v1（10人，仅文字描述）→ 全部克隆 ❌
- v2（10人，加Cynthia/Huxley立绘）→ Cynthia出现，Huxley位置不对 ⚠️
- v3（8人，立绘+轮廓型差异+锚点前置）→ Cynthia左前、Huxley右前，两人一眼识别 ✅

**翻车警告**：即使有立绘，如果把关键人物放在远景深处（第4、5位），仍然可能被遮挡或简化——永远把需要被认出的人放在**镜头最近的位置**。

## 14. 透视失真——俯视/大特写镜头是 Seedance 弱档之一

**问题**：写"近俯角 30-45° 俯视桌面"等抽象俯角描述时，模型常退化为正俯航拍 90° 或纯平面贴图，失去空间纵深感。文字层面的俯角形容词几乎不被响应。

**根因**：Seedance 对"俯角度数"的语义解析弱，遇到俯视描述倾向于退化到训练分布里最稳定的两个解：航拍 90° 或平面贴图。

**修复 SOP（写大特写 / 俯视镜头时强制执行）**：

- **摄像机位置具体化**：写"摄像机位于 X 后上方 Y cm，朝桌面斜下俯视，与桌面平面形成约 N° 夹角"——给几何参数（位置 + 夹角），不要只写抽象俯角词
- **物体梯形透视**：纸张/桌面/书本等矩形物体写"近宽远窄、左右随俯视收缩"，让模型显式渲染梯形透视
- **解剖透视参照**：手部写"手腕端靠近镜头略大、指尖端远离镜头略小"；人物上半身写"肩近膝远的透视收缩"
- **道具投影倾斜**：横放道具（笔/纸/钥匙）写"-10° 至 -15° 投影倾斜"——绝对水平的投影会被模型理解为正俯
- **⑧段必加防御**：禁正俯航拍 90°、禁纯平面贴图、禁解剖比例失真

**翻车案例**：EP5 shot_2 v1（手背压痕特写）写"近俯角 30° 俯视桌面"→ 出片是绝对水平的平面贴图，桌面无纵深、手部解剖比例失真。v2 改为"摄像机位于手腕后上方约 25 cm，与桌面成 35° 夹角；纸张近宽远窄，手腕端略大、指尖端略小"才稳定。

## 15. 物理元素持续性弱档——大幅运动末段"伴随物凭空消失"

**问题**：动作戏末段（坠落、跌倒、转身、推门）椅子、桌子、文件等"伴随物"突然消失或淡化为半透明，破坏空间连贯性。

**根因**：Seedance 偏好"画面焦点清晰简洁"——主体姿态被反向校准 ×2 强调时，模型为突出主体会主动"清掉杂物"。**主体越被强调，伴随物越易被清场**。这是 Seedance 视觉稳定性优化器的副作用（参考 deep-analysis.md 一）。

**修复 SOP（动作链镜末段强制执行）**：

- **⑥段每段（含末段姿态稳定期 + 三重静止收尾）都要主动写**"X 物体作为持续可见的核心物理元素清晰存在于画面 Y 位置"——把伴随物作为视觉主语之一，不只是背景
- **三重静止收尾必须并置锁定**：写"画面 Y 位置 X 物体完整可见 + 主体 Z 姿态——形成 W 构图"（构图层把伴随物和主体一起锁）
- **⑧段加专项防御**：禁止 X 在画面任何时刻消失/淡化为半透明/被构图简化掉
- **赋予伴随物叙事价值**：写"X 既是 A 的物理证据·也是下一镜 B 的视觉锚点"——给模型"为什么不能清掉它"的语义理由

**翻车案例**：EP5 shot_4b v1（椅子翻倒 + Sylvia 坠地 + X 形护腹）写"椅子向左侧翻"+ 坠地动作被强调 ×2 → 末段椅子完全消失，Sylvia 单独跪在空地。v2 在 ⑥段每个时间段都写"侧翻椅子持续位于画面左下 1/3 位置·椅腿朝向镜头清晰可见"，三重静止收尾写"侧翻椅子完整可见 + Sylvia X 形护腹姿态——形成倒地构图三角"，⑧段禁"椅子消失/半透明/被遮挡为不可辨"。v2 椅子稳定贯穿全镜。

## 16. L4 突发动作链镜的音频生成层根因

**问题**：眩晕/坠落/失控/打斗/突发动作画面跑视频生成时返 `OutputAudioSensitiveContentDetected`。

**关键洞察**：**ARK 安全过滤不基于 prompt 文字，而基于模型实际生成的音频流内容**。Prompt 文字层面再怎么改"动作音中性词"（"轻微擦地声"）都无效——**画面有失控内容，模型就会"贴心"生成对应的敏感音效**（哽咽/呼吸急促/物体撞击声），然后被自家安全模型拦掉。

**与 #9 TTS 英文敏感词的区别**：
- **#9 是文本层敏感词** → 改对白文字即可绕过
- **本条是音频生成层** → 必须从画面动作强度入手

**L4 突发动作链镜的音频 SOP**：

- **⑦段照抄静止镜的"安静"模板**——只写环境底噪 + 1 个稳定环境音（鸟啼/挂钟）+ 极低单音配乐平稳无变化
- **明确写**"全程无任何动作拟声·禁止任何强度高于环境底噪的非语言声响"
- **用 fast 模型而非 standard**——standard 画面理解更深反而易触发对应音效；fast 音频生成更保守反而通过
- **⑧段加禁**："任何动作拟声 / 哽咽 / 呼吸急促 / 配乐瞬停 / 物体撞击声"
- **三轮都失败**走 `--no-audio` 静音版生成，剪辑阶段叠加 BGM

**翻车案例**：EP5 shot_4a（眩晕预兆 + 文件滑落，6s 突发动作）连续 3 次返 `OutputAudioSensitiveContentDetected`。前两次保留了"文件滑落到地的轻响"和"Sylvia 短促吸气"这类"中性"音效描述——但模型实际生成的滑落音和吸气音被自家安全模型识别为危险信号。第 3 次⑦段彻底改为"全程仅环境底噪 + 远处鸟啼·禁止任何动作拟声·禁止任何呼吸声"+ fast 模型，才通过。

## 17. 视频 PolicyViolation 是概率事件，先重跑再改 prompt

**问题**：返 `OutputVideoSensitiveContentDetected.PolicyViolation`（copyright restrictions）。

**关键结论**：ARK 视频版权检测**有显著概率成分，不是固定拦截**。同一个 prompt 不同次运行结果不同。

**与 #16 音频拦截的区别**：

| 拦截类型 | 性质 | 第一反应 |
|---|---|---|
| `OutputAudioSensitiveContentDetected` | 基本固定（音频生成层根因） | 改⑦段音效层 + ⑧段禁动作拟声 |
| `OutputVideoSensitiveContentDetected.PolicyViolation` | 显著概率成分 | **先重跑 1-2 次**，连续 3 次都拦截才考虑改 prompt |

**SOP**：
1. PolicyViolation 第一次出现 → 立即重跑（同 prompt、同模型、同参考图）
2. 第二次仍 PolicyViolation → 再重跑一次
3. 连续 3 次都拦截 → 才考虑改 prompt（检查是否有版权敏感视觉元素：明显商标 / 现实人物形象 / 引用知名画面构图）

**反模式**：第一次 PolicyViolation 立刻改 prompt → 浪费一次正确的 prompt + 引入新变量 + 把"概率事件"误判为"prompt 错误"。

## 18. OSS 预签名 URL 24h 过期——跨日承接硬阻塞

**问题**：跨日跑续镜时报 `InvalidParameter / resource download failed` 在 `content[N].video_url`。

**根因**：上传到 OSS 的视频 URL 是预签名 URL（含 `X-Tos-Expires=86400` 等参数），有效期 **24 小时**。次日续镜引用昨日生成的视频 URL，签名已失效，网关侧下载失败。

**修复**：跨日承接的镜头 frontmatter **去掉** `previous_video_url` + `assets.videos`，仅靠 `previous_frame_url`（本地 PNG，base64 inline 不过期）做姿态承接。代价是丢失上一镜的动作惯性和镜头运动信号，仅保留末帧静态姿态——L4 突发动作链不建议这样做。

**预防**：

- 每集首镜起的 24h 内是连续生成的甜区——**尽量当天跑完整集**
- 跨日生产前先验证视频 URL 是否过期：

```bash
# 提取签名时间，对比当前时间
cat {作品}/episodes/ep_{N}/videos/{shot_id}.mp4.url \
  | grep -oE 'X-Tos-Date=[^&]+|X-Tos-Expires=[^&]+'
# 或直接 HEAD 一下
curl -sI "$(cat {shot_id}.mp4.url)" | head -1   # 应返回 200
```

- 若必须跨日续镜，优先方案：**重新上传上一镜本地视频文件** → 拿到新预签名 URL → 续镜引用新 URL

**翻车案例**：EP5 shot_4a 与 shot_4b 跨 24h 生成，shot_4b 引用 shot_4a 的视频 URL 时报 `resource download failed`。修复路径：去掉 `previous_video_url` + `assets.videos`，改为仅 `previous_frame_url` 承接末帧 PNG。
