# Novel Evaluator — 小说改编适配性评估

当用户提供一部小说的全文或 Bible 时，**系统性评估其是否适合改编为 moonshort 互动游戏**，并给出明确的 GO/NO-GO 决策。

## 核心原则

**你不是在做文学评审，你是在做改编策划。**

正确的思维方式："这些原材料，我能榨出什么？" 而不是"这些原材料，有哪些不达标？"

但同时，有些原材料确实不适合改编——门控的意义是尽早识别，避免在不合适的素材上浪费大量工作。

## 目标romance trope

所有评估必须基于这个受众：
- **北美 18-24 岁女性**
- 她们更像小说读者而非短剧观众
- 在乎 **slow-burn 拉扯感**，不要纯爽
- 付费动力 = "我的选择影响了关系走向" + "这个角色琢磨不透"
- 喜欢的场景：high school、mafia、大学校园、职场、小镇秘密、吸血鬼
- 不喜欢：需要大量前置知识的世界观（修仙、狼人 Fate Bond、宫廷权谋）

---

## 工作流（严格按顺序，禁止跳步）

### Step 1 — 输入与产物目录

- 源放在 `novels/{book-slug}/`
- `book-slug` 用 kebab-case(英文/拼音),不含空格或中文
- 可以是单文件(`novel.txt`),也可以是分章多文件(`ch01.md` / `Bad Idea One.md` 等任意命名)
- 如果用户直接粘贴全文 → 先 `Write` 到 `novels/{book-slug}/novel.txt` 再继续
- 如果只给 Bible(非全文) → 跳过 Step 3 和 Step 4,直接进 Step 5,最终报告里标注 "Bible-based,置信度低"

所有产物落在 `moonscripts/{book-slug}/01-novel-evaluator/`(先 `mkdir -p`):
- `reading-log.md` — 阅读日志(Step 3)
- `review-report.md` — log 审查结果(Step 4)
- `evaluation-report.md` — 最终评分报告(Step 6)

**路径安全**:文件名可能含空格、中文、Unicode 符号(例 `ʚїɞ │Bad Idea One.md`)。所有 Bash 命令里的路径**必须用双引号包裹**;能用 `Read` / `Grep` / `Glob` 就不用 shell 命令。

---

### Step 2 — 识别正文范围 + 写 log 头部

**目标**:把"真正有内容的文件"和"纯 divider/空页"分开,后者跳过不读不计入覆盖率。

**规则**:
- 用 `Glob` 列出 `novels/{book-slug}/` 下所有 `.md` / `.txt` 文件
- 对每个文件用 `wc -m "path"` 算字符数
- **字符数 ≥ 500** → 候选纳入阅读范围
- **字符数 < 500** → 视为 divider/占位页,跳过

**去重检测(concat dump 文件)**:
- 一些下载器会同时产出分章文件 **和** 一个整本拼接 dump(如 `*_full.md`、`{书名}_complete.txt`)
- 检测方式:如果存在某个文件的字符数 ≈ 其他所有候选文件字符数之和(±5%),该文件即是 concat dump
- **排除它**,只读分章文件。否则内容会被双重计数,覆盖率分母错误膨胀一倍

**多文件场景**:每个非占位、非 dump 文件 = 一"章"(即使文件名不含 "Chapter N")。
**单文件场景**:按一级标题 `^# ` 切章;切出的段字符数 < 500 的同样视为占位。

识别完成后,把结果全部写进 `reading-log.md` 头部(透明可查):

```markdown
# Reading Log — {书名}

## 范围识别
- 源目录: `novels/{book-slug}/`
- 总文件数: N
- 纳入阅读(≥500 字符): N_read 个,累计 N_chars 字符
- 跳过(占位页 <500 字符): N_skip 个

### 已跳过清单(供用户核对)
- `xxx.md` (147 字符) — Part divider
- `yyy.md` (442 字符) — 空白 aesthetic 页
...

## 阅读范围
- 语种: 中 / 英 / 混合
- 引语长度档: 中文 10-30 字 / 英文 20-100 字符
```

如果用户认为某个"占位页"其实有内容要读,用户会在这一步之后提出,agent 补读并追加 log。否则 agent 直接继续 Step 3。

---

### Step 3 — 边读边记 log（反作弊，强制执行）

**铁律（违反任一条 = 作弊）：**

- 每读完一章**立即**追加一行 log，**禁止**读完全书再回填
- 引语必须 **verbatim**（逐字复制原文），不是复述/改写/翻译
- 三条引语分别来自该章的**前 1/3、中 1/3、后 1/3**（保证分布式阅读）
- 引语长度按语种分档(Step 2 已记录):
  - **中文**:每条 10–30 字
  - **英文**:每条 20–100 字符(约 5–20 个词)
  - **混合语种**:就近取档,英文段用英文档,中文段用中文档
  - 原则:够短便于 grep,够长避免 grep 撞车(短于 15 字符的英文短语可能撞 N 处)

**`reading-log.md` 的章节表格式**(接在 Step 2 头部之后):

```markdown
## Log 表

| 章 | 文件 | 字数 | 起始行 | 摘要(≤2 句) | 引语1(前1/3) | 引语2(中1/3) | 引语3(后1/3) |
|----|------|------|-------|-----------|-------------|-------------|-------------|
| 1  | `06_Bad Idea One.md` | 25870 | 1 | Malia 和 Easton 开学前一天打篮球... | "It happens every time I think of Mauricio Reyes." | "Not bad for a girl wearing combat boots" | "See you tomorrow at school, Myers." |
| 2  | ... | ... | ... | ... | ... | ... | ... |
```

**字段说明**:
- `章`:按阅读顺序编号,不必对应原书章名
- `文件`:源文件名(多文件场景)或"单文件 L{起始行}-{结束行}"
- `字数`:该章的字符数,用于覆盖率计算
- `起始行`:该章在源文件里的第 1 行行号(用于 Step 4 的位置分段验证)

---

### Step 4 — Log Review 门控（必须 PASS 才能进 Step 5）

在 log 写完后，**本 skill 必须自己执行以下三项检查**，结果写入 `review-report.md`。

**检查 1 — 章节覆盖率 ≥ 95%**
- 分母 = Step 2 纳入阅读的文件数 N_read(不含占位页)
- 分子 = log 表实际有 entry 的章数
- 覆盖率 ≥ 0.95 → pass,否则 FAIL

**检查 2 — 字数覆盖率 ≥ 95%**
- 分母 = Step 2 已读集合的累计字符数 N_chars(不含占位页)
- 分子 = log 表"字数"列求和
- 覆盖率 ≥ 0.95 → pass,否则 FAIL

**检查 3 — 引语抽查（grep 验证）**
- 抽查数量 K = max(8, 章数 × 20%)，向上取整
- 从 log 里**均匀**挑选 K 条引语（覆盖前中后不同章）
- 对每条用 `Grep` 在源文件里搜：
  - 搜不到 → **作弊嫌疑**，整体 FAIL
  - 搜到但位置不在声称的分段（前/中/后 1/3）→ **作弊嫌疑**，整体 FAIL
  - 搜到且位置正确 → pass

**`review-report.md` 格式：**

```markdown
# Log Review Report

## 覆盖率(分母 = Step 2 过滤占位页后的阅读集合)
- 章节: M_log / N_read = X / Y = Z%  [PASS / FAIL]
- 字数: sum(log.字数) / N_chars = X / Y = Z%  [PASS / FAIL]

## 引语抽查（K 条，命中+分段双验）
| # | 章 | 引语 | grep 命中 | 位置分段正确 | 结论 |
|---|----|------|----------|-------------|------|
| 1 | 3  | "..." | ✓        | ✓            | pass |
| 2 | 7  | "..." | ✗        | —            | FAIL |
| ...|

## 总结论: PASS / FAIL
（如 FAIL，列出具体原因和最可能的原因：跳读 / 编造引语 / 位置声明错误）
```

**FAIL 时禁止进入 Step 5**。必须回到 Step 3 重新读漏掉的章节、补全引语。

### Step 5 — 评分（6 维，每项 10 分，总分 60）

#### 维度 1：MC 主动性（10 分）

评估女主角是否在推动关系和剧情，能否让玩家扮演她做真实选择。

| 分数 | 标准 |
|------|------|
| 9-10 | MC 有明确目标和内在矛盾，主动做关键选择，有多个"玩家可扮演"的决策时刻 |
| 7-8  | MC 有目标，大部分时间主动，偶尔被动 |
| 5-6  | MC 有反应但缺乏主动推动，部分决策由她做出 |
| 3-4  | MC 大部分时间被推着走，剧情由男主驱动 |
| 1-2  | MC 完全被动，纯工具人，无法代入扮演 |

#### 维度 2：LI 池厚度（10 分）

有几个无血缘关系的男性角色具备独立人格和可攻略潜力？

| 分数 | 标准 |
|------|------|
| 9-10 | 3+ 个有差异化人格的可攻略角色，各自有"表层≠内层"结构 |
| 7-8  | 2-3 个，但需要中度改编才能让全部角色立体 |
| 5-6  | 1-2 个有厚度，其余需要大幅重建或从世界观中新增 |
| 3-4  | 只有 1 个真正有人格的男性，其余全是工具人 |
| 1-2  | 全员工具人，没有可攻略感的角色 |

#### 维度 3：题材零解释成本（10 分）

北美 18-24 岁女性能否在第一秒进入场景规则？

| 分数 | 标准 |
|------|------|
| 9-10 | High school / Mafia / 大学 / 职场 / 小镇 — 零前置知识 |
| 7-8  | 吸血鬼 / 富豪家族 — 流行文化已建立认知，微量解释 |
| 5-6  | 轻奇幻 / 异能 — 需要 1-2 集建立规则但不复杂 |
| 3-4  | 狼人 Pack 体系 / 架空历史 — 需要大量前置解释 |
| 1-2  | 修仙 / 玄幻 / 东方宫廷 — 北美受众完全陌生 |

#### 维度 4：选择主导性（10 分）

他靠近她、开始在乎她，是因为她（玩家）做了什么，还是因为某种外部力量安排好的？分数越高 = 玩家的选择越能主导关系走向。

这个维度检测所有形式的「玩家选择被架空」，包括但不限于：
- 超自然宿命（Fate Bond、灵魂绑定、预言）
- 故事格式规则（真人秀节目安排、相亲配对机制）
- 契约/制度安排（商业联姻、强制合同、上级指派）

关键区分：「被迫接近」本身不扣分。高中同班、Mafia 欠钱、邻居——这些都是被迫接近，但如果他从「公事公办」到「开始在乎你」的转变可以被玩家的选择触发，就没有问题。有问题的是那种「不管你做什么他都会靠近你/爱上你」的设定。

| 分数 | 标准 |
|------|------|
| 9-10 | 他靠近她、在乎她，完全是因为她做了什么/说了什么/表现了什么。没有任何外部力量替玩家做这个决定。 |
| 7-8  | 接近有外部原因（同班/邻居/同事/欠债），但他态度的转变是玩家的选择触发的。 |
| 5-6  | 接近和态度转变各有一半是外部安排、一半是玩家选择驱动。可以通过改编调整比例。 |
| 3-4  | 他靠近她主要因为外部设定（节目规则/合同义务/家族安排），玩家的选择只是锦上添花。 |
| ≤3 = 致命 | 他靠近她完全因为命运/设定/规则，和她做了什么没有关系。包括：Fate Bond / 真人秀配对 / 不可违抗的契约 / 预言指定。 |

#### 维度 5：爽点类型（关系拉扯 vs 揭秘反转）（10 分）

爽点来自关系拉扯还是身份/信息揭露？

| 分数 | 标准 |
|------|------|
| 9-10 | 纯关系拉扯：靠近→推远→靠近的循环，slow-burn 结构天然 |
| 7-8  | 以关系拉扯为主，辅以适量身份/信息揭露 |
| 5-6  | 关系拉扯和身份揭露各半 |
| 3-4  | 爽点主要靠身份揭露（"她其实是首富之女"） |
| 1-2  | 纯靠反转和揭秘，没有真实的关系张力 |

#### 维度 6：天然分叉点（10 分）

有几个情节节点天然适合设计为有真实后果的玩家选择？

| 分数 | 标准 |
|------|------|
| 9-10 | 5+ 个天然分叉点，每个都能分出有代价的不同路径 |
| 7-8  | 3-4 个天然分叉点 |
| 5-6  | 1-2 个明显的，其余需要改编创造 |
| 3-4  | 线性剧情，几乎没有天然分叉，需要大量改编 |
| 1-2  | 完全线性，无法找到合理的分叉点 |

---

### Step 6 — 输出评估报告

所有内容写入 `moonscripts/{book-slug}/01-novel-evaluator/evaluation-report.md`，格式见下。

## 门控决策规则

```
总分计算：六项得分之和（满分 60）

IF 任意单项 ≤ 3:
    → NO-GO（致命短板，无法通过改编弥补）
    → 说明哪一项是致命短板及原因

ELSE IF 总分 ≥ 36:
    → GO（适合改编，进入 character-architect）

ELSE IF 总分 30-35:
    → CONDITIONAL（有改编潜力但存在硬伤）
    → 列出必须修改的硬伤
    → 由用户决定是否继续

ELSE IF 总分 < 30:
    → NO-GO（不建议改编，建议换书）
    → 说明核心问题
```

## 特殊情况处理

### 如果原著是中文网文
- 需要额外评估"北美化"的难度——场景、社会关系、文化隐喻是否需要全部替换
- 如果核心爽点是"纯爽"（身份揭露、打脸复仇），直接扣维度 5 的分
- "国内短剧思维"做出来的东西在北美不 work，这是已验证的结论

### 如果原著只有 1 个男主
- 不要直接判死刑
- 评估世界观是否能容纳新角色（如 Mafia 的五大家族天然可以加人）
- 评估男二或配角的改编潜力
- 如果世界观封闭（如两人独处荒岛），LI 池厚度打低分

### 如果原著存在「选择被架空」的设定

**超自然宿命类（Fate Bond / 灵魂绑定 / 预言）**
- 选择主导性维度大概率 ≤ 4
- 但要检查：这个宿命能否被改编为「邀请而非命令」——命运给了一个信号，但选不选是玩家的事
- 如果宿命是故事的底层架构且无法绕过 → ≤ 3，致命

**真人秀/恋综/配对节目类**
- 男嘉宾靠近女主是节目规则安排的，和女主的行为无关 → 选择主导性 ≤ 3
- 这类设定的核心问题是：玩家花钱做的选择感觉「没有后果」，因为不管选什么他反正都会在你身边
- 如果恋综设定可以改为「他本来是来工作的，但因为你做了某件事他开始认真了」，可以救回来

**契约/强制安排类（商业联姻 / 被指派的保镖 / 合同关系）**
- 接近本身是强制的 → 这没问题，很多好故事都是被迫接近
- 关键看：他的态度变化是被合同要求的，还是被玩家的行为触发的？

**总原则：被迫接近不扣分，被迫产生感情才扣分。**

## 禁止事项

### 评分/报告层面
- **不要虚高打分**：每个分数必须有小说中的具体证据支撑（引 log 章号）
- **不要在评估阶段开始改编**：评估只判断适配性，不做具体改编方案
- **不要忽略致命短板**：任一维度 ≤ 3 就是 NO-GO，不能用其他高分项弥补
- **不要用作家视角评判**：这不是书评，是产品适配性测试
- **不要硬塞 Wattpad trope**：如果一本小说不属于 top 11 的任何一个，如实标注"不归属"并自由描述

### Log 纪律层面（违反即整体 FAIL）
- **不要批量回填 log**：每章读完立即写 log，不许读完整本再一次性补
- **不要复述/改写引语**：必须逐字复制原文
- **不要自己声称位置分段**：前/中/后 1/3 必须真实对应章节内位置
- **不要跳过 Step 4**：review 未 PASS 禁止进评分，否则整份报告作废
- **不要擅自把占位页计入覆盖率分母**：<500 字符的文件在 Step 2 就被排除,不影响覆盖率分数

### 工具使用层面
- **路径必须引号包裹**：文件名可能含空格/中文/Unicode 符号,shell 命令里忘引号会静默失败
- **优先 Grep / Read / Glob,其次才是 Bash**：dedicated 工具对 unicode 文件名更稳
